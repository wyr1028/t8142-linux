# PMGR `devices` 属性 —— 结构解码

把 `/arm-io/pmgr` 节点的 `devices` 二进制属性(本机 18576 字节)解出来的结果。

工具:[`tools/pmgr_devices.py`](../tools/pmgr_devices.py)。
来源纪律见 [PROVENANCE.md](PROVENANCE.md) —— **本页开头那段"来源诚实说明"必须一起读**。

---

## ⚠️ 来源诚实说明(先读这个)

**本项目作者在与 AI 的同一会话中,曾接触过上游 m1n1 仓库 `src/pmgr.c` 的前 135 行。**

具体分界:

| 内容 | 是否独立从数据推出 |
|---|---|
| **48 字节定长记录**(387 × 48 = 18576,精确吻合) | ✅ 是 |
| **名字在记录偏移 32 处,16 字节 NUL 结尾** | ✅ 是 |
| **哪些字节位置会变化**(0/4/8/12/16/24 变,20/28 恒 0) | ✅ 是 |
| **数值字段是小端** | ✅ 是 |
| 字段的**命名**(`id` / `addr_offset` / `psreg_idx` / `group` …) | ❌ 否 —— 这些标签受那段源码提示 |

所以:**结构可信,字段名是标签,语义未确证。** 要确证语义,必须在真机上做读写实验。

---

## 1 结构

```
blob = N × 48 字节,N = len(blob) / 48

每条记录:
  [0 .. 31]   32 字节字段区
  [32 .. 47]  16 字节 NUL 结尾名字
```

本机:**387 条**,387 × 48 = 18576 = 精确等于 blob 长度。

**387 条全部有名字**(无空名记录)。

---

## 2 字段观察

| 偏移 | 宽度 | 观察 | 推测 |
|---|---|---|---|
| 0 | 4 | 同族相同,跨族不同:`ECPU_*`=`0x20000`,`PCPU_*`=`0x50000`,`ECPM`=`0x3020000` | 标志 + 父设备号打包 |
| 4 | 4 | 102 种取值 | 未定 |
| 8 | 4 | 3 种取值 | 未定 |
| 12 | 4 | 小端计数,逐条 +1 | 序号 |
| **16** | **3+1** | 低 24 位是**字节偏移**:`ECPU_0..5` = 0,8,16,24,32,40;**步长 8**;高 8 位是 group,本机只有 `{0,1,2}` | **power-state 寄存器偏移 + 组号** |
| 20 | 4 | 恒 0 | — |
| **26** | **2** | 小端;**范围 1..561,不连续** | **设备号(稀疏)** |
| 28 | 4 | 恒 0 | — |

### 2.1 最有价值的两个字段

**偏移 16(24 位 offset + 8 位 group)**:这是 `t8132-pmgr.dtsi` 里每条 power-state 的
`reg` 的来源。本机观察到的步长是 **8 字节/设备**,最大值 **65656**(≈ 0x10078)。

**偏移 26(设备号)**:范围 1..561 且稀疏 —— 说明 M5 的设备号空间比实际设备数大,
这正是 m1n1 需要"枚举"而不是"遍历"的原因。

## 4 ⭐ 地址结构已解开

PMGR 的地址**不是**"一个偏移"就够的,而是:

```
绝对地址 = base(group) + offset
```

**base 从哪来** —— pmgr 节点的 `ps-groups` 属性(36 字节 = 3 条 × 3 个 u32):

| group | reg_idx | base 实际值 |
|---|---|---|
| 0 | 0 | `0x170700000` |
| 1 | 1 | `0x178280000` |
| 2 | 48 | `0x370e80000` |

`base = pmgr 的 reg 属性第 reg_idx 条地址`
(本机 `reg` 864 字节 = 54 条 64 位小端 `(addr, size)`)。

### 4.1 关键:虚拟域与真实域

**记录字节 0 是 flags,`0x10` = 虚拟域。**

- 387 条里 **246 条是虚拟域** —— 它们**没有真实寄存器**,是 PMGR 合成的状态域
- 去掉虚拟域后剩 **141 条**,它们的 `(group, offset)` **全部唯一**
- 此前看到的"86 条偏移都是 0",**全是虚拟域** —— 不是数据出了问题

这一条解开了"132 条偏移重复"那个死结。

### 4.2 还没解决的

| 问题 | 怎么解决 |
|---|---|
| 141 条里还有 3 组 offset 撞车(6 条) | 定清 pmgr 的 `ranges` 怎么表达多基址 |
| 偏移 4/8/24 的语义 | 真机读写实验 |
| 虚拟域要不要在 DTS 里表达 | 上游 M4 的 dtsi 里没有可参考的写法 |
| 141 条里 Linux 真正需要哪些 | 与 M4 对照(已做,见 [PMGR-DELTA](PMGR-DELTA.md)) |
