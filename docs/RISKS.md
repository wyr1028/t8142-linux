# 实操风险(机器 / 数据 / 时间)

> 这份讲**机器和数据**的风险。
> **法律**风险在 [../LEGAL.md](../LEGAL.md),两码事,别混。

---

## 结论

**只有 M1(点亮 m1n1)会伤到机器。其余步骤要么完全可逆,要么只是浪费时间。**

| 阶段 | 风险 | 会伤机器吗 | 最坏结果 |
|---|---|---|---|
| M0 备第二台机器 | 极低 | 否 | 白跑一趟 |
| **M1 点亮 m1n1** | **高** | **是,唯一一步** | **丢数据 / macOS 起不来** |
| M2 采原始 ADT | 低 | 否 | 白跑 |
| M3 摸差异 | 低 | 否 | 得出"要几年" |
| M4 生成骨架 | 低 | 否 | 无 |
| M5 写设备树 | 低 | 否 | 编不过 |
| M6 引导内核 | 低 | 否 | 内核不启动 |
| M7 外设 | 低 | 否 | 无 |

**为什么 M2 之后都安全**:它们全在 m1n1 / 内核层面折腾,**不碰 macOS 的启动策略**。
引导失败最多是选错启动项、重启回 macOS。持久状态不变。

---

## 单独说:进 m1n1 本身有风险吗

**结论:跑起来之后风险很低。真正的风险全在"怎么装"那几条命令上。**

| 风险 | 评估 | 为什么 |
|---|---|---|
| 丢数据 | ✅ **基本没有** | m1n1 跑在内存里,**默认完全不碰磁盘** |
| 弄坏硬件 | ✅ **极低** | 它是 Asahi 安装器的一部分,M1~M4 上被大量使用 |
| 污染 macOS | ✅ 没有 | 不是装进 macOS,是**替代**它启动这一次 |
| 机器卡死 | ⚠️ 有可能 | 断电重启即可,不留痕迹 |
| 要 DFU 才能救 | ⚠️ 极端情况 | 有 DFU 兜底就没事 |

**m1n1 和你之前折腾的东西不一样:它不写你的盘。** 启动、初始化硬件、给个命令行,然后就待着。

### 唯一的真实不确定性

**M5 base 版上没人跑过 m1n1。** 它的 M5 支持是初始级的,且在 **M5 Max** 上测的。
表现可能是卡住 / 奇怪输出 / 自己重启 —— **不是"烧了"。**

### 出问题的上楼梯

```
卡住 → 断电重启,按住电源键,选 macOS
     → 还不行:恢复环境 / Apple Configurator(M3 MBA)
     → 最坏:DFU 恢复(抹盘,但有验证过的备份)
```

**每一级都有牌。**

## M1 的四个子风险

### 1. 写错卷 → macOS 起不来(最实际)

`kmutil configure-boot -v <卷>` 如果指到 macOS 自己的卷上,可能让它无法启动。

**缓解**:动手前把"我要装到哪个卷"写下来,确认那不是 macOS 卷。

### 2. 走到 DFU 恢复 → 抹盘(真正的损失面)

DFU 恢复会清掉机器上的数据。

**缓解**:**备份是硬前置,不是"最好有"。** 而且要**验证备份能恢复**,不是"我跑过一次 Time Machine 就完了"。

### 3. 安全等级被降低 → 长期敞口

`bputil -nkcas` + `csrutil disable` 降的是这台机器的**安全基线**:

- SIP 关闭 → 系统文件可被篡改
- Secure Boot 降低 → 内核扩展无签名限制
- 日常使用就带着这套降低的基线在跑

**这是可逆的,但要你主动恢复**:

```bash
csrutil enable      # 在 1TR 或 Recovery 里跑
```

### 4. `bputil` 参数用错

参数含义搞错,改出来的 boot policy 不可预期。

**缓解**:先 `bputil --help`,读懂了再敲。手册里那句别照抄。

## 可逆性的诚实评估

Apple Silicon 的恢复能力强。**真正意义上的"变砖"(连 DFU 都救不回)基本不可能。**

所以风险的本质不是"机器报废",而是:

1. **丢数据**(DFU 恢复会抹盘)
2. **要花时间修**(另一台 Mac + Apple Configurator + 重装)
3. **安全等级被长期降低而忘了恢复**

第 1 条才是真正要防的。

---

## 两个不在步骤里、但更该注意的

### A. 降安全之后的日常使用(最容易忘)

做完 M1 之后,你面对一个**冲突**:

- 恢复 SIP → m1n1 可能起不来
- 不恢复 → 日常带着降低的安全基线用

**没有两全**,这是这条路线的固有代价。你需要明确选一个:

- **方案一**:这台机器就当实验机,接受降低的安全
- **方案二**:平时恢复 SIP,每次要玩 m1n1 时再切过去(麻烦但安全)

### B. 数据外泄 —— `~/m5-adt.plist`

原始 dump 里有:序列号、UUID、MAC 地址、`uid-aes-key`、`SEPApNonce`。

已经写进 `.gitignore`,但:

> ⚠️ `.gitignore` 只挡得住 `git add -A`,**挡不住手动 `git add -f`**。

**缓解**:外发前**必须**过一遍 `tools/scrub_adt.py`,不靠记性:

```bash
# 生成只含结构的安全版本(默认只留 name / compatible / device_type / reg)
python3 tools/scrub_adt.py ~/m5-adt.plist -o ~/m5-adt-topology.txt

# 发布前自查 —— 有敏感字段则退出码 1
python3 tools/scrub_adt.py --verify <要外发的文件>
```

实测:原始 dump 里有 **87 处**敏感字段(2026-10-11)。白名单式输出比黑名单可靠 ——
想不到的敏感键不会被漏掉,因为它们本来就不在白名单里。

## 🚨🚨 真实案例:有人**误抹了整个盘**(包括固件和恢复环境)

来源:`ImAtomiskk/asahim5` 的 `notes/unrelated.md`(**同一台机器 J704**)。

> Selected "Macintosh HD" in Disk Utility from **recoveryOS** and clicked **Erase**.
> Normally macOS prompts "this is the main drive, do you want to reset your Mac instead?"
> — **this prompt never appeared**, and Disk Utility erased the entire disk
> **including firmware and recoveryOS/1TR**.

**诱因**:他们推测是**"之前的折腾改动了系统状态"**,导致 Disk Utility
没认出那是启动卷,于是当成普通卷抹掉了。

> ⚠️ **"之前的折腾" = 就是做了 m1n1 那套之后。** 换言之:
> **做过 M1 之后,在恢复环境里用磁盘工具是危险的。**

### 恢复代价

- **~6 小时**(7-8 小时减去走弯路的)
- **不需要第二台 Mac** —— 纯 Linux + `libimobiledevice` 就行
- **最难的一步:恢复环境没了之后怎么进 DFU** ——
  他写"**exact method forgotten — research this before next incident**"

### 对我们的三条行动

1. **⭐ 先下好签名有效的 IPSW 存着** —— 这是唯一事后补不了的
2. **做过 M1 之后,别在恢复环境里碰磁盘工具的 Erase**
3. **提前搞清楚"没有恢复环境时怎么进 DFU"** —— 别等出事了再查
